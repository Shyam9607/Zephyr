## Tasks

<task type="auto">
  <name>Task 1: Create minimal PlatformIO spike configurations for Arduino and ESP-IDF</name>
  <files>
    scratch/spikes/arduino-nimble/platformio.ini
    scratch/spikes/arduino-nimble/src/main.cpp
    scratch/spikes/espidf-nimble/platformio.ini
    scratch/spikes/espidf-nimble/src/main.c
    scratch/spikes/espidf-nimble/CMakeLists.txt
    scratch/spikes/espidf-nimble/src/CMakeLists.txt
  </files>
  <action>
    Create isolated, minimal PlatformIO spike projects targeting the ESP32 DevKit V1 (ESP32-WROOM-32 family):
    1. In `scratch/spikes/arduino-nimble`:
       - Configure `platformio.ini` for `board = esp32doit-devkit-v1`, `framework = arduino`, and include the `NimBLE-Arduino` library.
       - Implement a minimal `src/main.cpp` initializing NimBLE device name and creating a stub BLE HID mouse service.
    2. In `scratch/spikes/espidf-nimble`:
       - Configure `platformio.ini` for `board = esp32doit-devkit-v1`, `framework = espidf`, enabling NimBLE via `sdkconfig.defaults`.
       - Create minimal CMake project files (`CMakeLists.txt` and `src/CMakeLists.txt`).
       - Implement a minimal `src/main.c` establishing an architecturally equivalent BLE HID mouse GATT service with an identical report descriptor (3 buttons + relative X/Y + vertical wheel), HID Information, Protocol Mode, and HID advertising appearance.
    
    AVOID: Implementing complex application logic or full Zephyr controllers in the spikes.
    USE: Minimal boilerplate necessary to instantiate the BLE HID stack and evaluate build reproducibility.
  </action>
  <verify>
    Test that project configuration files and source entries exist in `scratch/spikes/` and are valid PlatformIO project layouts.
  </verify>
  <done>
    Both spike directories are initialized with minimal, reproducible PlatformIO configurations.
  </done>
</task>

<task type="auto">
  <name>Task 2: Execute builds and record local empirical measurements</name>
  <files>
    scratch/spikes/BENCHMARK_REPORT.md
  </files>
  <action>
    Using the local PlatformIO CLI (`& "$env:USERPROFILE\.platformio\penv\Scripts\pio.exe"`):
    1. For `arduino-nimble`:
       - Measure clean build duration (`pio run -t clean` followed by timed `pio run`).
       - Measure incremental build duration (touch source file followed by timed `pio run`).
       - Record RAM usage (RAM data/bss) and Flash utilization (text/data bytes and partition percentage).
       - Record platform, toolchain, and library versions.
    2. For `espidf-nimble`:
       - Measure clean build duration (`pio run -t clean` followed by timed `pio run`).
       - Measure incremental build duration (touch source file followed by timed `pio run`).
       - Record RAM usage and Flash utilization reported by the toolchain.
       - Record platform, toolchain, and ESP-IDF versions.
    3. Document all raw data, command invocations, and test environment details in `scratch/spikes/BENCHMARK_REPORT.md`.

    AVOID: Guessing numbers or using third-party web figures.
    USE: Actual local compiler outputs and elapsed execution timings.
  </action>
  <verify>
    Check that `scratch/spikes/BENCHMARK_REPORT.md` exists and contains actual measured values for clean build time, incremental build time, flash size, and static RAM for both environments.
  </verify>
  <done>
    Empirical measurements are fully captured, documented, and reproducible.
  </done>
</task>
