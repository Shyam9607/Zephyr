# Plan 1.1 Summary: Minimal PlatformIO Build Spikes & Local Empirical Benchmarks

## Overview

Plan 1.1 established two isolated, minimal PlatformIO spike projects targeting the ESP32 DevKit V1 (`esp32doit-devkit-v1`) to evaluate the architectural capability and resource footprint of **Arduino + NimBLE** versus **ESP-IDF + NimBLE**.

Both spikes were configured to test the exact same architectural capability:
- Minimal BLE HID mouse service (0x1812)
- Identical 50-byte report descriptor (Report ID 1) with 4-byte report payload:
  - 3 physical buttons (Left, Middle, Right)
  - Relative X movement (-127..127)
  - Relative Y movement (-127..127)
  - Vertical scroll wheel (-127..127)
- Device Information Service (DIS 0x180A) with Manufacturer String and PnP ID
- HID Mouse appearance advertising (0x03C2)

Neither spike implements Zephyr application domain logic, MPU6050 sensor processing, gesture filters, profiles, or persistent config storage.

## Empirical Benchmark Findings

| Metric | Arduino + NimBLE | ESP-IDF + NimBLE | Delta (ESP-IDF vs Arduino) | Notes |
| :--- | :--- | :--- | :--- | :--- |
| **Framework Version** | `espressif32 @ 6.10.0` / Arduino `2.0.17` | `espressif32 @ 7.1.3` / ESP-IDF `v5.3.2` | Newer upstream IDF toolchain | Both PlatformIO managed |
| **Flash Utilization** | **591,501 bytes** (45.1% of 1.31 MB) | **446,237 bytes** (42.6% of 1.05 MB) | **-145,264 bytes (-24.6%)** | ESP-IDF is 145 KB leaner in flash |
| **Static RAM** | **35,684 bytes** (10.9% of 327,680 bytes) | **27,132 bytes** (8.3% of 327,680 bytes) | **-8,552 bytes (-24.0%)** | ESP-IDF allocates 8.5 KB less static RAM |
| **Clean Build Time** (cached packages) | **19.43 seconds** | **155.81 seconds** (~2 min 36s) | **ESP-IDF is 8.0x slower** | ESP-IDF builds entire component tree |
| **Incremental Build Time** | **4.04 seconds** | **5.20 seconds** | **Comparable (+1.16s)** | Fast developer iteration on both |
| **Workspace Path Handling** | Works out-of-the-box with spaces | **Fails if path contains whitespace** | Tooling constraint | Requires `subst` or no-space directory |
| **Local Toolchain Disk Size** | ~360 MB | ~1.5 GB | **ESP-IDF is ~4.2x larger** | Python venv + 30 packages + tools |

## Deviations & Methodology Notes

1. **HID Equivalence Alignment**: The ESP-IDF spike was updated from initial BLE stack initialization to a complete GATT table matching the Arduino spike's 50-byte report descriptor, 3 buttons, X/Y movement, wheel, and DIS service to ensure genuine architectural equivalence.
2. **Whitespace in Workspace Path**: ESP-IDF's PlatformIO builder script (`espidf.py`) contains a hard assertion rejecting directory paths containing whitespace (`Error: Detected a whitespace character in project paths.`). Because the repository path is `d:\Projects\Zephyr - Airmouse`, a virtual drive mapping (`subst Z: "d:\Projects\Zephyr - Airmouse"`) was used to execute the ESP-IDF build without mutating repository paths.
3. **Hardware Validation Pending**: No hardware test was performed or claimed. Validation on target hardware remains paused pending arrival of the physical USB cable.
4. **No Framework Selection Made**: In accordance with user instructions, no framework selection or ADR-0009 drafting was performed in Plan 1.1. Empirical comparison data has been gathered first.
